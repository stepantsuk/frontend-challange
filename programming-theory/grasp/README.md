# **GRASP**

-----

**GRASP** - шаблоны / правила проектирования, используемые для решения задач по назначению обязанностей / распределения ответственности между классами / объектами. Задача - определение какие классы должны быть в системе, их обязанности/задачи и взаимодействия между ними. 

Существуют 9 шаблонов, которые описаны в книге Крейга Лармана "Применение UML и шаблонов проектирования".

Обязанность - ключевое слово данного каталога паттернов.

Обязанности знаний - объекты, обладающие информацией о закрытых инкапсулированных данных, связанных объектах и вычисляемых величинах.

Обязанности действий - объекты выполняющие действия. Этими операциями могут быть вычисления и исполнения алгоритмов, инициирование и исполнениях действий у других объектов.  

GRASP шаблоны не имеют четко выраженной структуры. Не ограничиваются только программным кодом. 

GRASP паттерны не имеют выраженной структуры, четкой области применения и конкретной решаемой проблемы - онипредставляют обобщенные подходы/принципы/реккомендации, используемые при проектировании дизайна системы. 

1) Информационный эксперт (Information expert). Означает, что объект/класс обладает необходимой/достаточной информацией для исполнения конкретной задачи (исполнения обязанностей).

2) Создатель (Creator). Создание объектов необходимо поручать тому классу, который содержит или агрегирует создаваемые объекты. 

3) Контроллер (Controller). Обработка внешних событий должна происходить в специальном слое-контроллере, который отделяет логику от представления.

4) Низкая связанность (Low Coupling). Необходимо стремиться к тому, чтобы классы/объекты имели низкую связанность между собой. Методы и данные (их получение/формирование) не должны зависеть от соседних классов/объектов.

5) Высокое сцепление (High Cohesion). Означает, что объект/класс, его обязанность должна быть узконаправленной.  

6) Полиморфизм (Polymorphism). Использование полиморфизма позволяет избежать условных конструкций, делегируя вариативное поведение подклассам.

7) Защищенная вариативность (Protected variations). Необходимо изолировать участки, которые наиболее подвержены изменениям, используя стабильные интерфейсы для минимизации влияния изменений.

8) Чистая выдумка (Pure Fabrication). Создание искусственных классов, которые не относятся к реальным сущностям из предметной области, необходимы для создания технических или сервисных классов. Это позволяет снизить связанность и увеличить когезию.

9) Перенаправление (Indirection). Введение посредников между объектами для ослабления прямых зависимостей и лучшей вариативности.
