# CORS

**Cross-Origin Resource Sharing (CORS)** — это механизм безопасности браузера, который контролирует доступ веб-страниц к
ресурсам (API, шрифтам, изображениям), находящимся на другом домене (протокол + домен + порт). Простыми словами, это
система правил, по которой сервер говорит браузеру: «этому сайту я доверяю, пусть читает мои данные, а этому — нет».

В основе безопасности браузера лежит политика одинакового источника (Same-Origin Policy). Она запрещает скриптам с сайта
evil.com читать ответы с bank.com. Это защищает пользователя от кражи данных.

**Как работает CORS (упрощённо)**

- Браузер (не сервер!) — главный исполнитель правил. Когда фронтенд с siteA.com пытается сделать AJAX-запрос на
  api.siteB.com, браузер проверяет, разрешает ли сервер api.siteB.com такие запросы.
- Сервер должен явно разрешить доступ, отправив специальные заголовки в ответе.
- Если разрешения нет, браузей блокирует чтение ответа (сам запрос может уйти, но JavaScript не получит ответ).

Не путать с **CSP** — CSP контролирует, какие скрипты/стили можно загружать на страницу, а CORS — можно ли читать ответ
от другого домена.

**Основные сценарии CORS**
1. Простой запрос (simple request)
   Браузер отправляет запрос и смотрит на заголовки ответа. Если есть нужный заголовок — отдаёт ответ скрипту, нет —
   блокирует.
   `Access-Control-Allow-Origin: https://siteA.com`
   Если сервер поставит "*", то разрешено с любого домена (но нельзя с credentials).
2. Предварительный запрос (preflight)
   Если запрос «непростой» (например, с нестандартным заголовком, методом PUT или DELETE, с Content-Type:
   application/json), браузер перед основным запросом отправляет OPTIONS-запрос (preflight), чтобы спросить разрешения.

Пример preflight-запроса:
```text
OPTIONS /api/data HTTP/1.1
Origin: https://siteA.com
Access-Control-Request-Method: POST
Access-Control-Request-Headers: Content-Type
```
Сервер должен ответить:
```text
Access-Control-Allow-Origin: https://siteA.com
Access-Control-Allow-Methods: POST, GET, OPTIONS
Access-Control-Allow-Headers: Content-Type
Access-Control-Max-Age: 86400
Только после положительного ответа браузер отправит основной POST.
```

**«Простой запрос» — это запрос, удовлетворяющий следующим условиям:**
- Допустимые методы для запроса:
    GET
    HEAD
    POST
- Кроме заголовков, которые автоматически проставляются user-agent'ом, допустимыми заголовками, которые могут быть проставлены вручную, являются:
    Accept
    Accept-Language
    Content-Language
    Content-Type
- Не должны быть зарегистрированы обработчики событий на любой объект XMLHttpRequestUpload
- В запросе не должен использоваться объект типа ReadableStream
